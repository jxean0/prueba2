# prueba2

1. @Controller es para devolver vistas (HTML, Thymeleaf, JSP); si un método devuelve un String, Spring busca una vista con ese nombre. @RestController es @Controller + @ResponseBody, así que todo lo que devuelven los métodos se serializa directo al cuerpo de la respuesta, normalmente como JSON. Por eso en proyectos como Wishlist o Football 5 usamos @RestController, porque son APIs puras, no devuelven páginas.
2. Porque exponer la entidad directamente es arriesgado: puede tener campos sensibles que no queremos mostrar, y suele tener relaciones (@OneToMany, @ManyToOne) que generan bucles infinitos al convertir a JSON o cargan datos de más por el lazy loading. El DTO nos deja controlar exactamente qué información sale, y además desacopla la API del modelo de base de datos, así si cambia la tabla no necesariamente se rompe el contrato con el cliente.
3. Con @PrePersist la fecha se asigna justo antes del INSERT real en la base de datos, dentro del ciclo de vida que maneja Hibernate. Eso garantiza que sea la fecha real de guardado, no la del momento en que se creó el objeto en memoria (que pueden ser instantes distintos). Además funciona aunque la entidad se construya con el constructor vacío que exige JPA, donde sería difícil inicializar la fecha manualmente.
4. ddl-auto=update compara el esquema actual con las entidades y solo agrega lo que falta (tablas, columnas), sin borrar datos existentes. ddl-auto=create borra todo el esquema y lo vuelve a crear desde cero cada vez que arranca la app, perdiendo los datos. En producción no se usa ninguno de los dos; lo correcto es validate (o none) junto con una herramienta de migración como Flyway o Liquibase, para tener control total y trazabilidad de cada cambio en la base de datos real.
5. Agregaría seguridad real con Spring Security y JWT para autenticación y roles, en vez de dejar todos los endpoints abiertos como en un proyecto académico. También un manejo de errores centralizado con @ControllerAdvice para devolver respuestas consistentes en vez de stack traces. Y por último, migraciones de base de datos versionadas con Flyway o Liquibase, junto con variables de entorno para las credenciales en vez de tenerlas escritas directamente en el código.
